# Prospective native timing engineering gate

The actual historical SNANA generator is available and now builds privately. A same-photon timing experiment is therefore feasible without reconstructing missing archived fluxes or substituting an iid Gaussian toy. The archived timing precision gate remains failed; this prospective experiment has a different, explicit estimand.

The frozen experiment uses the metadata-selected LIBID 11 cadence: 117 retained source exposures, comprising 111 optical and six J/H measurements. The source peak is changed prospectively from 57707.8 to the exactly representable native-R4 value 57707.80078125; exposure timestamps remain unchanged. Redshift is also set to its native-R4 value, with CMB-apex and peculiar-velocity terms disabled, so the controlled heliocentric and distance redshifts coincide. These are declared engineering conditions, not a reproduction of the historical survey simulation.

Eight fixed stochastic attempts use the released SNooPy_B18 model, the released DES/NIR KCOR file, known stretch 1, AV 0 and RV 1.518, MW law 94, and no intrinsic OIR/model/lensing scatter. Observation noise still uses the actual native generator: its Gaussian draws have source/sky/read variance, and its reported flux variance subsequently changes with the realized source flux. Every native flux/error pair is retained, including negative measurements. The unchanged author error map is deliberately not remapped; its field names do not match this cadence, so the source predicts no extra error-map variance. The component ledger must confirm this.

For each realization, the joint grizJH fit estimates only peak and amplitude. A paired NIR fit then changes only its fixed peak from truth to that same-realization joint estimate. The NIR photons, errors, flags, nuisance values, calibration and accepted physical rows remain identical. This directly tests the timing/noise correlation that an independent Gaussian peak perturbation misses. It does not import the archived joint fit's fitted stretch or extinction.

Native errors and weighting remain distinct. The generator writes FITS MJD as R8 and flux/error as R4; the fitter retains its own historical R4 coordinate behavior. The new 17-digit ledger is an internal truth/noise record, not a claim that the input files or fitter preserve all R8 coordinates. Native model-error covariance and its iteration updates remain active as declared; they are not equated to the injected measurement covariance. The native peak prior also remains active and is recentered between iterations. Thus this is a test of a specified native estimator, not a prior-free peak estimator or a parameter-dependent-covariance maximum-likelihood analysis.

The driver has three released stages: generation identity/accounting, noiseless closure, and the eight stochastic paired fits. The original and output-instrumented generators must give identical native HEAD/PHOT table values. The noiseless original and support-instrumented fitters must reproduce every saved mean, inverse covariance, objective and FITRES science row exactly. Noiseless distance recovery must be within 0.001 mag, peak recovery within 0.01 day and the largest mean residual within 0.02 quoted error. The numerical gates additionally cover iteration 9 versus 12, distinct initial peak/amplitude coordinates, native error flags, fixed-C amplitude stationarity, unchanged masks and a null peak adapter.

A broad accepted-epoch window does not limit the optimizer's trial peaks. Native MINUIT permits approximately ±100 days at initialization. The private support build therefore records all USRFUN evaluations before template/KCOR work, including initialization and covariance evaluations. Plotting is disabled. It reports phase, shape and redshift extrema, all unsupported/nonfinite counts, and the first offending coordinates. The table range [-20,70] is a numerical support boundary, not independent empirical validation. Any unsupported evaluation or missing support summary stops the engineering gate; no new optimizer bound has been inserted.

The resource limit is one native worker, 120 seconds total and 40 seconds per process, including all replay/null/start/iteration controls. There are eight unique noisy realizations, one exact replay of those eight for generator equivalence, and one deterministic mean control. The planned 16 fitting processes contain 107 fit records; the three generation processes add up to 19 native processes. Failed attempts are preserved, never replaced until a desired sample size is reached. Native GENRANGE rejection can retry even with NGENTOT_LC, so the ledger requires exactly eight actual attempts and zero hidden rejects or forced accepts.

Only per-draw engineering quantities are saved: fitted peak error, each NIR distance error against the internal synthetic distance, and their paired distance difference. A successful gate permits a separate design for 64 fresh draws; that stage is neither frozen nor authorized by this document. No selection-normalized survey correction, population dust result or corrected cosmology follows from this conditional experiment.

The precise executable specification is [protocol.json](protocol.json), with [run_engineering.py](run_engineering.py) and [freeze.json](freeze.json). The root must supply a release file binding both hashes and the permitted stages. No prospective photons or fits had been generated when these files were frozen. Earlier malformed pre-execution cadence and incomplete control drafts remain preserved; [input-amendment-v3.json](input-amendment-v3.json) records the fixes. Private generator builds consumed 21.921 seconds and the separate support-fitter build consumed 15.194 seconds; shared binaries were not modified.
