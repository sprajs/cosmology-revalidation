# Literal SIMLIB ID-lock failure and isolated amendment

The original v3 process failed while reading a cadence, before GENMAG_DRIVER/GENFLUX_DRIVER and before any written event. It left README/LIST/DUMP initialization products, but HEAD and PHOT are zero-byte files and DUMP contains its header only. Its native active time, 17.047889647001284 seconds, remains charged to the unchanged 120-second engineering cap.

The exact v11_04d source contains two superficially conflicting paths. Main-loop lines 366–367 can set a lock to the first accepted LIBID when INPUTS.SIMLIB_IDLOCK is 1. However, SIMLIB_findStart first takes every nonnegative IDLOCK literally, seeks that value, and at line 15066 assigns GENLC.SIMLIB_IDLOCK=INPUTS.SIMLIB_IDLOCK. The initial pre-read can reach LIBID 11 while the GENLC lock is still -9. The later cadence reader then applies keep_SIMLIB_HEADER, whose nonnegative-lock condition rejects ID 11 when the stored lock is 1. No event can reach the later main-loop “first accepted” assignment. The reader wraps until its fixed 100000-try abort.

The intended scientific cadence was already frozen as LIBID 11. The additive v4 inputs therefore change only SIMLIB_IDLOCK: 1 to SIMLIB_IDLOCK: 11, plus output-directory version names needed to retain the failed run. All exposure lines, truth parameters, random seed, noise/selection settings, numerical gates and overall resource cap remain unchanged. No measurement realization was rejected and no seed was searched. This is a source-control configuration repair, not an outcome-dependent science change.

The original protocol, executor, input files, failure JSON, native log, resource ledger and initialized output files remain untouched. `protocol-v4.json`, `freeze-v4.json` and `run_engineering_v4.py` form the new executable set. Its separate activity ledger begins with the exact earlier failure record, so the remaining native budget is 102.95211035299872 seconds. A new root release is required; preparation did not execute native code.
