# Original DES RAISIN LIBID 11 cadence audit

I parsed the original `DES_RAISIN.simlib` LIBID 11 without using the derived cadence builder or generating photons. The source SHA-256 is `a357e6ce…`; the [protocol](protocol.json), [audit script](audit.py), [735-row physical epoch ledger](physical-epochs.csv), [result](result.json), and [manifest](manifest.json) make the calculation inspectable. Every row of the separately prepared 735-row cadence ledger matches this independent parse in source line, ordinal, exposure ID, band, MJD, nominal phase and keep flag.

The original block declares `NOBS: 735` and contains exactly 735 `S:` rows, exposure IDs 0–734 without duplication. All 735 `(MJD, band)` keys and even all printed MJD keys are unique. `RA=54.520306`, `DECL=−29.391666`, `MWEBV=.006`, `PIXSIZE=.27`, `FIELD=DES16E1dcx`, `REDSHIFT=.453`, and `PEAKMJD=57707.8` are source header fields.

The prospective configuration requests `USE_SIMLIB_REDSHIFT=1`, `USE_SIMLIB_PEAKMJD=1`, `VEL_CMBAPEX=0`, and `GENSIGMA_VPEC=0`. The v11_04d source computes actual generated epoch rest phase as `(MJD−PEAKMJD)/(1+GENLC.REDSHIFT_HELIO)` ([snlc_sim.c:10407–10413](../raisin_2021_selection_accounting/source/snlc_sim-v11_04d.c:10407)); its heliocentric conversion returns zCMB unchanged at zero apex velocity and zero peculiar velocity ([13436–13478](../raisin_2021_selection_accounting/source/snlc_sim-v11_04d.c:13436)). Some SIMLIB pre-window logic uses zCMB, so this equality is specific to the prospective controls, not a general identification of the redshift frames. The intended private header uses float32-representable peak `57707.80078125` and z `0.453000009059906`, promoted to double for phase arithmetic. **The first private draft (`inputs/`, SHA-256 `b1481ad…`) was malformed and omitted a parseable redshift/peak header.** The original block's `.453/57707.8` values are distinct by a tiny representational shift. The corrected v2 check below closes the private header gate without erasing this failure.

At the planned fixed coordinates, inclusive rest phase `[-15,+45]` selects **117 of 735** original physical rows: `g27, r28, i28, z28, J3, H3`. Selected nominal phase spans **−14.999161 to +44.908616 days**. The planned peak is 0.00078125 observer days later than the source header. If that same nominal 117-row cohort were evaluated over a prospective peak domain of ±4 observer days, its rest phases would span **−17.752086 to +47.661540 days**, entirely inside the separate `[-20,+70]` fit guard. This is a coordinate-support check, not a guarantee of native accepted rows or unchanged generation membership.

If the `[-15,+45]` generation window were *reapplied* at peak−4 or peak+4, it would select 115 or 109 rows, respectively; 102 rows pass at every peak in the domain and 122 at some peak. Those are hypothetical membership geometries only. The fixed prospective generation is intended to retain its nominal 117 input epochs.

All numeric cadence fields are finite. Across the original 735 rows, gain is 1, read noise is 0, sky sigma is 6.68–561.37, PSF1 is .55–3.83, PSF2/ratio are 0, zeropoint is 28.23–35.33, and zeropoint error is 0–.086. The source's `PSF_UNIT: ARCSEC_FWHM` and positive pixel scale make the PSF1 values parseable under the documented SIMLIB convention. `MAG=99` in every row is the SIMLIB placeholder. These checks establish no empirical validity of exposure noise or photometry.

The first derived private SIMLIB was not executable as claimed. This report contains no generated/observed fluxes, model brightnesses, fits, or distance outcomes.

## Corrected v2 input check

After the malformed draft was preserved, the preparer wrote `inputs-v2/cadence.simlib` (SHA-256 `856cf82c…`, manifest SHA-256 `4c27face…`). My separate [v2 verifier](verify_v2.py) and [result](v2-result.json) check every manifest file hash, the structured metadata headers, and all **117 `S:` exposure lines byte-for-byte and in source order** against the original 735-row ledger. The corrected header has `NLIBID: 1`, `LIBID: 11`, `NOBS: 117`, source RA/DEC/MWEBV/pixel scale and `FIELD: DES16E1dcx`, plus exact private `REDSHIFT: 0.45300000905990601` and `PEAKMJD: 57707.80078125`. It retains `PSF_UNIT: ARCSEC_FWHM` and terminates with `END_OF_SIMLIB: 1 ENTRIES`. All checks pass.

All three `generation-v2/{original,ledger,noiseless}/sim.input` files point to `../../inputs-v2/cadence.simlib` and keep `USE_SIMLIB_PEAKMJD=1`, `USE_SIMLIB_REDSHIFT=1`, `GENRANGE_TREST=-15 45`, `VEL_CMBAPEX=0`, `GENSIGMA_VPEC=0`, and `VPEC_ERR=0`; no HOSTLIB override appears. Thus, for this corrected **configured** input, source-frame logic gives zHEL=zCMB=`0.45300000905990601` for phase. This remains metadata feasibility; it does not claim a generated event, a native accepted mask, or measured exposure-noise validity.

At that fixed coordinate, the source `GENRANGE_TREST` pre-window has unpadded observer MJD bounds **57686.0057811141 to 57773.1857816577** ([v11_04d `set_SIMLIB_MJDrange`](../raisin_2021_selection_accounting/source/snlc_sim-v11_04d.c:16980)). The 117 selected source rows all lie inside; the native `keep_SIMLIB_OBS` lower/upper tests use `<` and `>`, so boundary equality is kept ([source](../raisin_2021_selection_accounting/source/snlc_sim-v11_04d.c:16888)). This checks the phase clamp's coordinate and inequality, but other native generation cuts and later fitting remain outside this metadata audit.
