# Independent review of the historical-source RAISIN refits

> Supporting research note. Scientific findings and limitations are preserved from the recorded investigation; historical result links identify the evidence available at that time. See the [study guide](../../README.md) for current execution status.

I independently parsed the native FITRES and LCPLOT tables under `fits-shortprefix`, the archived author FITOPT000 table, and the frozen corrected [protocol](../specifications/experiments/raisin_historical_native/fit-protocol-shortprefix.json). The parser and machine result are [check.py](../code/experiments/raisin_historical_native/independent-review/check.py) and [result.json](https://github.com/sprajs/cosmology-revalidation/blob/17487bf659fcbdeeea072221492bac14b04a0a85/runs/research_2026_09_26/raisin_historical_native/independent-review/result.json). All 346 recorded protocol, parent-input, and summary-output hash entries match; all 29 job execution records report zero return code and the corrected protocol hash. Parent fit, spread, baseline, and paired-response CSVs agree with independent values. This review did not run or rank any fits.

There are 270 full native records: 240 primary old-source/default-law-94 fits (10 objects × 4 input arms × free/fixed peak × 3 starts) and 30 old-source/law-99 free-peak R controls. All 270 FITRES rows report `ERRFLAG_FIT=0`, `RV=1.518`, and `RVERR=0`. In all 120 fixed-peak fits, fitted PKMJD equals the input PKMJDINI to printed precision. Every full output contains the ten declared CIDs. For each object, accepted LCPLOT `DATAFLAG=1` rows satisfy `NDOF = accepted − number of free parameters`. All 80 primary three-start cases have identical accepted-row multisets, including duplicate band/MJD/flux keys. Thus their distance spreads are not explained by different accepted masks.

The printed primary distance spread exceeds 0.001 mag in 35/80 cases and 0.01 mag in 25/80. The maximum is 0.39153 mag for DES16E2cqq, fixed peak, R arm, with the same accepted rows at all starts. These are numerical start sensitivities under this source/configuration, not a preferred minimum or a physical correction. FITCHI2 is data-only while the fit includes a peak prior and iterated covariance; it cannot by itself rank runs under a proven common full objective.

The nominal old-law-94 R/free/start-1.0 fit is exceptionally close to the archived author baseline: seven of ten DLMAG values are identical at printed precision; maximum absolute distance difference is 0.00019 mag, median zero. All ten NDOF values match. The largest corresponding differences are 0.00012 in AV, 0.00001 in stretch, 0.0118 day in peak date, and 0.00377 in printed data FITCHI2. This strongly links the source-version/configuration baseline to the archived output at table precision, while leaving the original binary, toolchain, and effective execution settings unproven.

The corrected engineering R and Rcopy FITRES **rows** match exactly, and their LCPLOT files are byte-identical. The whole FITRES files differ only in the expected `VERSION_PHOTOMETRY` header (`RSR_R` versus `RSR_Rcopy`). The original long-prefix engineering attempt remains invalid and outside these counts: historical `sntools_output_text.c:65,219` stores an output prefix in a 100-byte buffer using unbounded `sprintf`, and that attempt produced a malformed output filename. The protocol amendment changed only to relative `TEXTFILE_PREFIX='fit'` inside isolated output directories; the source and science inputs were retained.

## Covariance qualification

If one mechanically forms a 3×3 matrix with diagonal `STRETCHERR²`, `AVERR²`, `DLMAGERR²` and the three printed `COV_*` off-diagonal entries, 105/270 such matrices have a nonpositive eigenvalue. For all 105, the negative eigenvalue magnitude exceeds a conservative Frobenius bound on every decimal-print rounding perturbation (and thus the operator-norm eigenvalue bound). The worst mechanical minimum eigenvalue is −0.00449, and a pairwise magnitude normalized by the printed errors reaches 9.55. **This does not show that the native MINUIT Hessian covariance is non-positive.**

The historical source explicitly mixes error definitions in that assembled table. `snana.car:37053–37117` stores `LCERR_STORE` from averaged upper/lower parameter errors, with a fallback to initial step for some bad errors. It obtains `FITERRMAT` separately from MINUIT `MNEMAT` at `snana.car:37125–37160`. `snlc_fit.car:17955–17970` sends `FITERRMAT` to the covariance columns, while `snlc_fit.car:18733–18744` sends `LCERR_STORE` to the parameter-error columns. Its covariance-fix routine explicitly warns that diagonal `FITERRMAT` is “not necessarily ERR²” (`snlc_fit.car:2868–2878`); the default `OPT_COVAR_LCFIT=0` (`:7027`) leaves that optional repair off. The print-rounding test proves only that rounding is too small to reconcile this *hybrid table construction*. The unprinted full `MNEMAT` diagonal and full optimizer state are required to test native-Hessian positive definiteness. `ERRFLAG_FIT=0` and the printed hybrid-matrix test address different checks; no PSD clamp or input-quality conclusion follows.

The source tag matches the FITOPT000 headers, and the tagged source was built with current local compiler/libraries. Neither source linkage nor the near-exact author table match establishes execution by the original historical binary.
