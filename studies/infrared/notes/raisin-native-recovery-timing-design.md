# Native recovery and archived-simulation timing: next computation

> Supporting research note. Scientific findings and limitations are preserved from the recorded investigation; historical result links identify the evidence available at that time. See the [study guide](../../README.md) for current execution status.

The recommended next computation is a **first-eight-object reconstruction gate, followed only if it passes by a paired NIR timing intervention**. It uses the archived simulation outputs instead of inventing a timing-error distribution. The completed optical native-template libraries could support a separate conditional sign-selection recovery, but that would add less decisive evidence now. Neither calculation can by itself supply a population distance or cosmology correction.

This review ran no native fits, new noise draws, distance differences or residual scores. It froze the [timing pilot protocol](../specifications/experiments/raisin_profile_solver_review/native-recovery-design/timing-pilot-protocol.json), SHA256 `1eed7ec4342929104ee567551b5663db6ef81ef03ce809a38a9cfb02624618e4`, and a [500-object membership ledger](https://github.com/sprajs/cosmology-revalidation/blob/17487bf659fcbdeeea072221492bac14b04a0a85/runs/research_2026_09_26/raisin_profile_solver_review/native-recovery-design/all500-membership.csv). The protocol hashes 23 source/input files, including the native binary, released model/KCOR and exact nominal NML. The [preparation script](../code/experiments/raisin_profile_solver_review/native-recovery-design/freeze_design.py) performs only metadata inventory and hashing. Execution is delegated to the separately owned simulation review; its runner and reconstructed files must be frozen before baseline scores.

## What the archived timing outputs identify

The independent [timing audit](raisin-simulation-timing-audit.md) finds 30,000 NIR fits with fixed peak equal to the initializer and a 0.010103-day population SD of initializer minus true simulated peak. Among 29,987 matching optical+NIR fits, fitted minus true peak has SD 0.545335 day and mean −0.067077 day. Printed initializers and selected generating fields match exactly on common CIDs. Both products name `DES_RAISIN_SIM` and SNANA v11_04k.

These facts identify two different timing inputs in the available simulated processing. They do not identify the uncertainty of real photometry headers. The optical+NIR peak is a fitted output from grizJH, can share J/H noise with the NIR distance, and also begins near the generating truth. No creator of the real observed `PEAKMJD` headers has been established by this review.

The source mapping is precise. Nominal [NIR SUBMIT.INFO](https://github.com/sprajs/cosmology-revalidation/blob/17487bf659fcbdeeea072221492bac14b04a0a85/runs/research_2026_09_26/raisin_simulation_execution_review/author/output/fit_nir/DES_RAISIN_NIR_SIM/SUBMIT.INFO) names `fit/sim/REFAC_DES_RAISIN_NIR.nml`; that [exact acquired NML](https://github.com/sprajs/cosmology-revalidation/blob/17487bf659fcbdeeea072221492bac14b04a0a85/runs/research_2026_09_26/raisin_simulation_assets/timing/REFAC_DES_RAISIN_NIR.nml) fixes stretch 1, AV 0, RV 1.518 and peak, fitting only distance from J/H. Nominal [joint SUBMIT.INFO](https://github.com/sprajs/cosmology-revalidation/blob/17487bf659fcbdeeea072221492bac14b04a0a85/runs/research_2026_09_26/raisin_simulation_execution_review/author/output/fit_all/DES_RAISIN_OPTNIR_SIM/SUBMIT.INFO) names [REFAC_DES_RAISIN_optnir.nml](https://github.com/sprajs/cosmology-revalidation/blob/17487bf659fcbdeeea072221492bac14b04a0a85/runs/research_2026_09_26/raisin_simulation_execution_review/author/fit/sim/REFAC_DES_RAISIN_optnir.nml), with free stretch, AV and peak and grizJH. Both set three iterations, `PRIOR_MJDSIG=5`, `TREST_REJECT=[−15,45]`, `OPT_XTMW_ERR=1`, `OPT_COVAR_FLUX=0`; commented MW-law 99 leaves historical default 94 active. Other similarly named `output/sim/...` NMLs refer to different SALT/OIR experiments and are not nominal substitutes.

In historical snlc_fit.car (`sources/repos/RickKessler__SNANA@v11_04k/src/snlc_fit.car:6950`; historical local reference), the free-peak default initial step is 2 days, the default first-iteration peak grid is −4,−2,0,+2,+4 days, and default prior width is 20 days. The NML overrides the last to 5. The source initially reads `SEARCH_PEAKMJD` at line 8103; FITINI_ADJUST (`sources/repos/RickKessler__SNANA@v11_04k/src/snlc_fit.car:9259`; historical local reference) can replace the peak initializer with the preferred grid point. At later iterations FITINI_PARVAL (`sources/repos/RickKessler__SNANA@v11_04k/src/snlc_fit.car:8043`; historical local reference) sets `INIVAL=FITVAL(previous)+FITERR(previous)*INIVAL_SHIFT_ERRFRAC`, whose default multiplier is zero, and returns before the first-only setup. The peak prior (`sources/repos/RickKessler__SNANA@v11_04k/src/snlc_fit.car:4995`; historical local reference) is centered on that current `INIVAL`. It remains enabled even with `OPT_PRIOR=0`; within its central range its chi-square is `(peak−INIVAL)^2/5^2`, with protective tail steepening near 28 days. A five-day fixed external measurement prior is therefore not the correct interpretation of the iterative calculation. The source match is not a historical executable/input-hash certificate.

## Available photometry and reconstruction gates

The [LCPLOT feasibility audit](raisin-simulation-lcplot-feasibility.md) identifies only the first 500 processing-order CIDs, 1–500, with 1,829 measured J/H rows. There are 69,200 model plotting points, which must never become observations, and no exported rejected-data rows. MJD is printed to .001 day, peak to .0001 day, and measured flux/error to five significant digits. The remaining 29,500 nominal NIR objects have no available epoch export here. CID 91 lacks a joint fit within the first 500; all thirteen missing joint fits across 30,000 remain a separate global ledger. The pilot is CIDs **1–8**, without replacements or exclusions based on timing, signal, distance, chi-square or convergence.

One important source refinement is that fitted LCPLOT comes from **SNLCPLOT(SNFIT)**, not merely the generic SNANA plot packer. At snlc_fit.car:18261 (`sources/repos/RickKessler__SNANA@v11_04k/src/snlc_fit.car:18261`; historical local reference), MJD is stored single-precision epoch offset plus `MJDOFF`; Tobs is the fitted epoch-phase slot, measured flux is `JEP_DATAFLUX`, and error is `JEP_DATAFLUX_ERR`. LOAD_EPALL (`sources/repos/RickKessler__SNANA@v11_04k/src/snlc_fit.car:10497`; historical local reference) sets the last from `SNLC_FLUXCAL_ERRTOT * FUDGE_DATAERR_SCALE`, whose default is one. Model-flux error and total fitter error are different slots. Thus the exported error is the preprocessed data error, not the full model/MW covariance. It can be replayed only after checking source preprocessing, avoiding a second application of error transformations, and reproducing the outgoing data-error column. Model/MW terms must still be handled by the nominal native settings; they are not subtracted from this error or replaced by a diagonal covariance.

The pilot preserves every exported measured row and its sign. It does not invent the omitted cadence or claim that a synthetic default PHOTFLAG reproduces missing raw flags. Source-gated metadata are required: observer-frame model redshift from the actual native `REDSHIFT_FIT` mapping, separate zHEL/zCMB/zHD/VPEC bookkeeping, printed MWEBV and its native interpretation, source SIM_LIBID-to-SIMLIB sky-position linkage if needed, and the source's floating-point header-peak parsing. Unknown input semantics stop the reconstruction rather than trigger an observed-data substitution.

Two work-local baseline copies use byte-identical inputs, historical v11_04k and short relative output/override paths. They must produce identical FITRES science rows and LCPLOT, with any irrelevant path/comment exclusions specified before execution. All eight require finite output, ERRFLAG zero, fixed-parameter closure, exact archived NDOF and accepted J/H `(band, printed MJD)` multiset. The predeclared archive-agreement caps are **0.001 mag in DLMAG** and **max(0.01,0.001×|archived data chi-square|)**. These are engineering closure thresholds, not a mathematically derived rounding envelope. Exported FITCHI2 is data chi-square rather than the full minimand, so it cannot rank different prior/covariance states.

The protocol separately quantifies input precision: half a last displayed decimal unit for each token, .0005 day for MJD and .00005 day for peak, plus the source's explicit float32 round-trip. It requests one-coordinate ± endpoint replay for epoch MJD/flux/error and relevant header values, then aligned endpoint combinations based on local D and chi-square sensitivity. The L1 first-order envelope and measured nonlinear remainder are reported as a **rounding sensitivity screen**, not a proof over every corner of the input box. If that screen exceeds the fixed engineering caps, changes a mask, or the nominal reconstruction fails closure, timing responses do not proceed under this protocol. Tolerances are never widened after the result.

The cap is **600 seconds, one worker**, with deterministic perturbation clones batched to avoid reinitializing the native model for every scalar change. There are 16 baseline object fits, roughly at most 400 small rounding/control fits and eight joint-time fits; actual row counts and the first process timing determine the logged forecast. An unfinished gate is reported as unfinished, not passed. No expansion to all 500 is included.

## Paired timing intervention and its meaning

After all reconstruction gates pass, change only the first eight photometry header peaks from their archived near-truth initializer `t_ini` to their own same-CID archived optical+NIR fitted `t_joint`. Retain identical reconstructed J/H fluxes, errors, epochs, redshift/MW inputs, model and native covariance iteration. Do not import optical shape/AV, draw new noise, add new intrinsic scatter, or replace measured flux by `SIM_FLUXCAL`.

The primary response is

`delta_i = D_NIR(y_i; t_joint,i) − D_NIR(y_i; t_ini,i)`.

Save each value, native state/failure/mask flag, rounding sensitivity, and the unweighted first-eight mean and empirical dispersion. Mask changes remain results; they cannot be silently mixed with a common-mask interpretation. Because only exported rows are reconstructed, a native cut-aware result is still conditional on that available row set. Unknown extra original epochs could enter a shifted phase window. A common fixed-mask extension would require its own explicit amendment.

Same photometry version, CID and printed generating fields support the paired-file interpretation but do **not** prove cross-branch epoch/noise identity. That assumption remains explicit unless raw simulation HEAD/PHOT or a joint-fit epoch table supplies the match. Even under that assumption, `t_joint` is endogenous: J/H photons enter its grizJH fit. Independently drawing timing errors with SD .545 day would discard this correlation. All archived ERRFLAG values being zero is also insufficient to prove joint-fit numerical uniqueness, given the native convergence findings elsewhere. The pilot is a response to the archived timing output, not a claim that it is the uniquely measured true time.

The generator's active `OIR.J19` scatter is already part of the simulated light curves. A timing-dependent NIR response could expose a difference between two processing choices, but its RMS cannot be added independently to an empirical OIR scatter or distance-error budget. If a later source gate establishes the precise simulated distance/scatter target and population membership, write `r=D_INI−D_true`. Then exactly

`Delta MSE = 2 E[r delta] + E[delta²]`,

`Delta Var = Var(delta) + 2 Cov(r,delta)`.

These identities show why timing SD alone does not quantify distance bias or extra variance. The current pilot does not score SIM_DLMAG residuals; SIM_DLMAG versus `SIM_gammaDM`, grey scatter and band/phase scatter must first have an explicit truth convention. Its first-eight mean cannot estimate a 30,000-object population correction.

Before any cosmology update one would additionally need representative/full simulation inputs, the actual observed timing estimator and its selection, raw photometry/noise identity, convergence and parameter-dependent covariance validation, detection/follow-up/cadence selection including sign omission, error calibration, and the downstream bias-correction and systematic-covariance accounting. The present intervention holds already generated scatter fixed and cannot establish that all these effects were historically omitted.

## Why the native sign-recovery library is deferred

The [original sign-selection proposal](raisin-selection-simulation-design.md) is preserved unchanged: two metadata-chosen DES cadences, three source-defined shape/AV truths, 64 paired realizations and four retention arms imply 1,536 primary native fits, before multistart checks. It includes native iterative covariance/initialization behavior and a declared generator; it is not silently replaced by the completed fixed-C profiles.

Each completed native mean library contains an outcome-independent **521-shape by 65-AV rectangular core**, plus extra coordinates selected while profiling the observed flux. A defensible new finite-library recovery would extract only that exact core; never use observed-adaptive nodes, observed best fits or fitted reference distances as generating truths. Nested 261×33 and 521×65 cores permit a discretization sensitivity check, not a claim of continuum optimization. The AV grid is empirical over [−1,2]; physical generating AV can be chosen nonnegative, but an empirical fitted AV is not automatically a passive-screen measurement. The source tabulation supplies the numerical shape/phase domain, not a validation of all possible populations there.

The original proposed truth AV values 0 and .3 are not on the 65-node AV grid. Source-chosen truth coordinates would therefore need fresh native means rather than nearest-grid substitution. Verified multiplicative distance scaling can transport library vectors to a separately specified generating distance, but native clipping/support and amplitude replay must be rechecked at those new distances and recovered extrema. The stored covariance is frozen at an observed state: using it as the generating covariance is an explicitly conditional engineering experiment, not a measured true noise model. Adding its model/MW contributions again as independent latent scatter would double count them.

For such a separate experiment, generate one complete noise vector on the supported author cadence and subset the same exposure-identified vector into full signed F, freshly positive T, archived-positive-mask M with new signed noise, and M plus fresh positivity MT. No sign folding, discarded failures or independent redraws are allowed. Source duplicate exposure identities and covariance exchangeability require explicit handling. Full Gaussian versus naive selected fits can use the finite family and analytic positive amplitude, preserving all competing shape/AV modes, distance boundaries and zero-amplitude failures. Correct censor/conditional estimators would additionally require their precise observation likelihood, not merely a product of independent positive normalizers.

A small 2-cadence ×3-truth ×16-realization ×4-arm version would yield 384 finite-family fits, not the original 1,536-native-fit calculation. It would test whether nonlinear native colour/phase/shape competition changes the already demonstrated sign-selection mechanism. It would still not identify the physical population, missing extraction covariance, joint error/flag distribution, persistent old/new noise correlation or historical correction. For that reason it is a fallback design, **not launched**: source-matched archived timing replay is currently the more direct new measurement of a concrete processing difference.
