# RAISIN fitter source-version review (read-only)

> Supporting research note. Scientific findings and limitations are preserved from the recorded investigation; historical result links identify the evidence available at that time. See the [study guide](../../README.md) for current execution status.

The optical FITOPT000 headers name SNANA `v11_04k`. The pinned source tag resolves to commit `0583dd7ed547c56093c4e1191c4a1c9af205389e`; all 212 files in the [acquisition manifest](https://github.com/sprajs/cosmology-revalidation/blob/17487bf659fcbdeeea072221492bac14b04a0a85/runs/research_2026_09_26/raisin_historical_native/acquisition.json) rehash exactly ([source check](https://github.com/sprajs/cosmology-revalidation/blob/17487bf659fcbdeeea072221492bac14b04a0a85/runs/research_2026_09_26/raisin_historical_native/source-review/source-check.json)). This establishes a plausible source version, **not** the binary, environment, configuration, or exact code that produced the archived fits. No fit or build was run for this review.

## Material configuration distinction

The archived RAISIN optical NML has `!OPT_MWCOLORLAW = 99` commented out (NML line 70 (`sources/repos/djones1040__RAISIN_DataRelease@a383c4b/lcfitting/REFAC_DES_RAISIN_optical_sys.nml`; historical local reference)). Historical `snana.car:225` defaults `OPT_MWCOLORLAW` to 94 (O'Donnell); modern `snana.F90:95` defaults to 99 (Fitzpatrick). Thus historical source plus unmodified NML implies law 94, while the modern controlled refits explicitly set 99. This is a real source/configuration distinction, subject to unknown original command-line or environment overrides. Holding 99 fixed in both source versions is a controlled implementation comparison; it does not reproduce the older default configuration.

## SNooPy B18 grid and interpolation

The old and modern `genmag_snoopy.c` differ only in info-file error handling, saved `fscanf` return, and unused-variable casts. The mathematical interpolation and pointer calculations in historical lines 182–304 are unchanged in modern lines 180–302. `INDEX_GRIDGEN` (old `sntools_modelgrid_read.c:514–537`, modern `:515–538`) is likewise unchanged. It clamps a parameter to the first or last index; the caller steps an upper-edge index back one cell, checks packed-LC markers and the low bits of the shape index, and bilinearly interpolates packed flux and error over phase and shape. The ratio bounds check is commented out (`genmag_snoopy.c:262–270`), so both source versions permit mathematical edge extrapolation; source equality alone says nothing about physical support.

The grid reader recomputes `BINSIZE` from actual first and last grid values divided by `NROW−1` (old `sntools_modelgrid_read.c:271–274`; modern `:271–278`). The actual pinned B18 FITS grid (`sources/repos/djones1040__RAISIN_DataRelease@a383c4b/model/snoopy.B18/SNooPy_B18.fits`; historical local reference) has 131 stretch rows from 0.7 to 1.3, actual step approximately 0.004615384; its `SNPAR-INFO` header says `BINSIZE=0.01`, which the reader does **not** use for this index. It has 91 phases −20 to 70 at step 1 and 9 filters. LOGZ, AV, and RV have one row each. Modern source adds an `NROW>1` guard and sets singleton `BINSIZE=0`; the old source divides zero by zero for those three singleton dimensions. The SNooPy interpolation directly indexes stretch and phase, whose computed bin sizes are finite in both, but singleton handling elsewhere and compiler floating-point behavior cannot be proven equivalent from this review.

## Prior, objective, covariance, and mask

Both versions construct a protective peak-date prior even with general `OPT_PRIOR=0` (old `snlc_fit.car:10791–10799`, modern `snlc_fit.F90:11277–11285`). It is centered on mutable `INIVAL(IPAR_PEAKMJD)` and scaled by `PRIOR_MJDSIG` (old `:4994–4997`, `:11099–11190`; modern `:4843–4850`, `:11745–11848`). The historical initializer can grid-search and replace that initial peak (`:9263–9322`); there are also later initial-value reset paths. Consequently the prior center need not equal a fixed released header peak. Both stored `FCN_FITCHI2` values exclude `CHI2INI` even though minimization includes it (old `:4224–4226`, `:4405–4410`, `:4858`; modern `:3941–3945`, `:4133–4139`, `:4623`). An archived FITCHI2 difference is a data-fit difference, not automatically a difference in the full changing optimizer target.

Both versions select full covariance after the first iteration when model-flux, MW-extinction, or fudge covariance is enabled (old `snlc_fit.car:9998–10009`; modern `snlc_fit.F90:10490–10502`). RAISIN's `OPT_COVAR_FLUX=0` disables model-flux covariance, **but does not make this fit diagonal**: its `OPT_XTMW_ERR=1` is copied into `OPT_COVAR_MWXTERR=1` (old `:7226`; modern `:7083–7084`), which activates MW covariance after first iteration. The old full-covariance objective leaves the determinant term commented out (`:4854`); modern code supports an opt-in `OPT_CHI2_SIGMA` log-determinant bit (`:4584–4617`), default zero (`:6842–6843`). Neither the archived NML nor controlled ordinary config requests that bit. The covariance is recomputed across iterations; this and changing accepted rows limit any claim that reported data chi-square values share one fixed objective.

The first-iteration epoch rejection logic is substantially shared (old `snlc_fit.car:4715–4744`, modern `snlc_fit.F90:4465–4493`): rest phase and MJD bounds, `DELCHI2_REJECT`, and `SIGNOISE_REJECT`, followed by `IEP_REJECT` flags. RAISIN sets `TREST_REJECT=-7,45`, `FUDGEALL_ITER1_MAXFRAC=0.02`, and has blank `EPCUT_SNRMIN`; the defaults for the other rejection controls are `DELCHI2_REJECT=1e9` and `SIGNOISE_REJECT=-9` in both sources. This supports testing the same mask mechanism, not assuming identical masks or minima across versions. The historical and modern fitter files have many changes outside the compared blocks; no whole-program identity is claimed.

The immediate historical-control interpretation is therefore: treat law-94 and law-99 as separate configurations, preserve start/mask/covariance diagnostics, and compare the stored FITCHI2 as data-only. Exact original execution remains unproven without its binary, effective settings, model/filter files, and runtime provenance.
