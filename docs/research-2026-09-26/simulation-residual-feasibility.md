# Existing simulation epoch-residual control: feasibility inventory

This is a source and file inventory, **not a simulation residual result**. No new simulation, classifier inference, fit, or residual score was run. The machine-readable [inventory](../../runs/research_2026_09_26/simulation_residual_inventory/inventory.json), its [read-only inspection script](../../runs/research_2026_09_26/simulation_residual_inventory/inventory.py), and the [SHA-256 manifest](../../runs/research_2026_09_26/simulation_residual_inventory/manifest.json) cover the nine existing `PH2_pilot02_*` arms. The script verified every original simulation output against its run manifest, FITS observation pointers against `NOBS` and sentinel rows, unique written CIDs, attempt-to-fit links, and the fitted-parameter covariance shape. Its only writes were its own inventory, manifest, and unexecuted command-candidate files.

## What the simulated flux already represents

The original [P21 input](../../phase2/literature/simulations/inputs/PH2_pilot02_P21.input) and its [SNANA README](../../phase2/literature/simulations/outputs/PH2_pilot02_P21/PH2_pilot02_P21.README) identify the DES SIMLIB, nominal DES KCOR, nominal SALT3.DES5YR surface, `DES_FLUXERRMODEL_SIM.DAT`, `SMEARFLAG_FLUX=1`, `SMEARFLAG_ZEROPT=3`, search-pipeline and host-redshift efficiencies, and detection/cut windows. SNANA source [adds search/template/fudge noise to true flux](../../phase2/official/build/SNANA-audit-v3/src/snlc_sim.c) around lines 28460–28500; its zero-point flag bits 1 and 2 respectively add zero-point scatter to true noise and reported error (around lines 27838–27880). These PHOT `FLUXCAL` values are therefore noisy mock measurements in the **fixed nominal** calibration/model convention, with configured measurement effects already simulated. They are not noiseless model curves, nor draws from the shared nine calibration/SALT surface covariance. The nine listed arms here are physical-population/noise alternatives, separate from the coupled `MODEL001`–`MODEL009` calibration/SALT variants inventoried in [shared-calibration-uncertainty.md](shared-calibration-uncertainty.md).

The saved original fit NML uses the nominal DES KCOR/SALT3 and F99 Milky Way settings; its fake-data error and chromatic correction lines are commented out with the source comment that these corrections are in the release and automatically ignored for simulations. Its phase/PSF/zero-point/iterative clipping can reject PHOT epochs. Since no original-arm `LCPLOT`, `LCLIST`, epoch mask, model-flux array, or per-object epoch covariance was saved, none can be reconstructed exactly from PHOT+FITRES alone. The `4×4` Hessian covariances above do not fill that gap. The separate `forward_p21_refit_covariance.npz` is likewise a fit-parameter product, not an epoch export.

There is an executable-era law distinction. The original simulation manifest uses historical `SNANA-2fe0f56`, where `OPT_MWCOLORLAW=99` means the older polynomial F99 approximation. The saved P21/G10 fit logs name `SNANA-current`, version `886408a4-output17g`, where [the built header](../../phase2/official/build/SNANA-audit-v3/src/MWgaldust.h) defines 99 as exact spline F99 and **-99** as the older approximation. The original forward NML says 99, so the saved fit baseline used the modern law. The candidate below preserves that fit baseline. A future matched-generator-law diagnostic would change only the new output-only fit's `OPT_MWCOLORLAW` to -99, explicitly separate from the historical saved-fit closure check; neither option recovers unrecorded historical epoch masks.

## Native exporter and selection closure

The real-data control used an instrumented SNANA [`snlc_fit.exe`](../../phase2/official/build/SNANA-audit-v3/bin/snlc_fit.exe) that prints `PHASE2_FLUX`, `PHASE2_COVINV`, and `PHASE2_OBJECTIVE` at the last accepted fit iteration; the output-only [`export_flux_objectives.py`](../../scripts/research_2026_09_26/export_flux_objectives.py) parses that log into per-CID observed/model epochs and full within-object covariance. The exporter **cannot read PHOT+FITRES directly**. The same executable can read the simulated FITS version and existing nominal fit coordinates, but it must make a new output-only fit pass. This would yield a new accepted-epoch mask and covariance under that executable, not retroactively recover the historical one. It requires explicit CID, measured-parameter, epoch-count, and accepted-observation identity checks before any residual score.

An [unexecuted P21 CID 16 candidate NML](../../runs/research_2026_09_26/simulation_residual_inventory/candidate_p21_cid16.nml) and [seed](../../runs/research_2026_09_26/simulation_residual_inventory/candidate_p21_cid16.seed.FITRES) demonstrate the command route. The candidate copies the original P21 fit config, adding only a one-CID measured FITRES seed, `LFIXPAR_ALL=T`, an LCPLOT request and an isolated output prefix. Its seed was inverted from the existing double-precision fit-parameter export, **not** `SIM_x0/x1/c` or `SIM_PEAKMJD`. It was not launched. A safe candidate command, in the project root, is:

```bash
SNANA_DIR="$PWD/phase2/official/build/SNANA-audit-v3" \
SNDATA_ROOT="$PWD/phase2/official/inputs/SNDATA_ROOT" \
LD_LIBRARY_PATH="$PWD/phase2/official/build/sysroot/usr/lib" \
  phase2/official/build/SNANA-audit-v3/bin/snlc_fit.exe \
  runs/research_2026_09_26/simulation_residual_inventory/candidate_p21_cid16.nml \
  > runs/research_2026_09_26/simulation_residual_inventory/candidate_p21_cid16.log
```

If and only if that future log ends gracefully, the existing exporter could process it with `--log <log> --output <new isolated directory> --expected-cids <CID list>`. The original NML's `DELCHI2_REJECT=10` remains; fixed coordinates do **not** prove unchanged epoch membership. A two-stage method would first preserve the original fit settings and independently check refitted FITRES membership/parameters, then freeze those **measured** coordinates in an output-only pass and compare fitted model, observed flux/error, and every accepted `(CID, band, MJD)` row to its first pass. The existing real author-mask path widened phase cuts and disabled clipping; importing those switches into a simulation control would change selection. The instrumented source is a later local build, so historical-fit identity must be measured, not assumed.

## Matching limits before any score

The saved FITRES `PKMJDINI` is a measured initial peak estimate, separate from fitted `PKMJD` and generator truth `SIM_PEAKMJD`; P21 CID 16, for example, has `57276.3711`, `57267.5703`, and `57266.3672` respectively. The released SuperNNova prediction stage windows epochs around **measured** `PKMJDINI` before PHOTFLAG rejection; substituting `SIM_PEAKMJD` would leak truth and change the input. The classifier reconstruction still fails its preregistered DES probability gate ([classifier audit](classifier.md)); no SNNV19 probabilities were computed for these nine arms. A generated-to-basic-quality comparison could therefore be labelled as such, but cannot be called a matched released `SNN>.999` null. SNTYPE 101/truth-Ia is not a replacement.

Field conditioning also needs a single rule. HEAD has no FIELD column. PHOT records an epoch FIELD, while FITRES may encode compound labels: P21 has 110 multi-field written objects, and 77 of its fitted FITRES FIELD strings disagree with the first PHOT FIELD; G10 has 115 and 76. The real observer control used the first PHOT epoch. Joining on FITRES FIELD silently changes the ten-field allocation; use the same first-PHOT rule with a documented multi-field sensitivity if a later protocol requests it.

Finally, these simulations use released 2024 assets and a relocated P21 alpha convention, not a byte-identical 2022 release mock ([simulation handoff](../../phase2/literature/simulations/HANDOFF.md)). Their population law, host/detection efficiencies, fixed nominal calibration, and basic quality stage have not closed the released full classifier/BBC membership. The [physical audit](../physics-audit/HANDOFF.md) found unsupported negative passive-screen extinction for part of the extrapolated low-`R_V` truth population; any result conditional on that population needs this support limitation stated, with no clipping or parameter retuning inferred from residuals.
