# CSP 42-object peak-header provenance audit

This is a read-only audit of the frozen 42-object cohort. The [machine-readable ledger](../../runs/research_2026_09_26/csp_native_filter_response/cohort-execution/header-provenance/full42-header-fit-ledger.csv) retains the released header, archived NIR FITRES, current replay, and three alternate author fit branches for every CID. All 42 released input headers map to the replay `PKMJDINI` after SNANA's float32 MJD encoding. For 41, they also map to the archived NIR initializer. The only substantive archived/released difference is `2007A`: released `PEAKMJD=54113.4336`, replay `PKMJDINI=54113.4336`, archived NIR `PKMJDINI=PKMJD=54113.4453`. Those input dates differ by 0.0117 printed day, exactly three float32 MJD units (0.01171875 day). The other 41 header strings often have fewer decimal places than FITRES; their float32 values agree, so their printed differences are rounding, not evidence of changed timing inputs. Archived versus replay redshift, peculiar velocity, MW extinction, stretch, host AV and RV FITRES fields agree for all 42. The baseline result still fails the frozen archived chi-square gate for `2007A` (+0.32136); no input was modified to force closure.

The author repository at pinned commit `b888214a5cbae38ac0bf886488ce7734f5b77e87` contains `2007A` optical and optical+NIR v11_04k FITRES with initializer **54113.4453**, the same as archived NIR. The optical+NIR fit reports a *fitted* `PKMJD=54113.4336`, equal to the current released photometry header; its optical-only fitted peak is 54113.3945. Across the cohort, all 42 archived NIR and optical+NIR initializers agree, but the optical+NIR fitted peak equals the released input for only 2/42. Thus the `2007A` equality is a direct asset match, not proof that the optical+NIR fit generated the header. An older author optical+NIR product has `2007A` initializer 54113.3008 and fitted peak 54113.4336. The author `fit_nir_sys_oldpkmjds` branch reports an earlier 54113.199 fitted peak and does not supply comparable `PKMJDINI` in its schema. These are distinct fit products, not interchangeable baselines.

The current released `CSPDR3_2007A.PKMJD.DAT` is byte identical to the author repository's latest tracked file (SHA-256 `699b5f8d8308b4075d3a54f34dd50aec701a4dc4bd51a3d0fdc66f3f83cac364`). Its five pinned file-history versions report 54113.21 (Aug 2020), 54113.20 (Oct 2020 and Jan 2021), 54113.3 (Apr 2021), and 54113.4336 (Jan 2022 onward). None of these tracked photometry versions reports 54113.4453. A transient input, private edit, or alternate preparation remains possible, but not established by the available Git history. The archived optical/optical+NIR initializers demonstrate that 54113.4453 was used by multiple archived fit branches, not a FITRES rounding error.

The [author acquisition manifests](../../runs/research_2026_09_26/csp_native_filter_response/cohort-execution/header-provenance/) verify exact Git blob IDs, sizes, and SHA-256 hashes for 11 selected small source assets, five photometry history blobs, and three supplemental FITRES blobs. The [summary](../../runs/research_2026_09_26/csp_native_filter_response/cohort-execution/header-provenance/full42-header-fit-summary.json) records counts and file hashes; the [script](../../runs/research_2026_09_26/csp_native_filter_response/cohort-execution/header-provenance/build_ledger.py) reads existing assets without fitting. Archived output and source-tag labels do not themselves prove the executed input bytes or command history.

The minimum defensible amendment for a *current released-input* paired filter relabel is to declare that estimand separately from reproduction of the historical archived FITRES, keep the same 42 objects, nominal coordinates, physical epoch masks, model and numerical gates in both arms, and preserve the `2007A` archive mismatch in its lineage ledger. It cannot be called an archived-fit replay. The still-failed six-object final-iteration stability gate also remains; a source-derived, separately frozen numerical amendment and independent review would be required before any full-42 changed-filter response is interpreted. No changed-filter fit or response calculation was performed in this audit.
