# RAISIN DES simulation fit execution provenance

This is a read-only audit of the pinned author repository at `b888214a5cbae38ac0bf886488ce7734f5b77e87`. Eleven small files were acquired, each checked against its Git blob ID and size; the [acquisition manifest](../../runs/research_2026_09_26/raisin_simulation_execution_review/acquisition.json) records SHA-256. No simulation or fit was run, and no large FITRES or light-curve file was downloaded.

## What the archived run records establish

The archived NIR [`SUBMIT.INFO`](../../runs/research_2026_09_26/raisin_simulation_execution_review/author/output/fit_nir/DES_RAISIN_NIR_SIM/SUBMIT.INFO) names `fit/sim/REFAC_DES_RAISIN_NIR.nml` as `ARG_LIST`, gives a 2021-11-11 14:01:26 submit time, and lists four completed jobs for `DES_RAISIN_SIM`, `DES_RAISIN_SIM_AVSYS`, `DES_RAISIN_SIM_AVSYS_2`, and `DES_RAISIN_SIM_STSYS`, each with `FITOPT000`. Its `ALL.DONE` contains `SUCCESS`. The author tree contains `output/fit_nir/DES_RAISIN_NIR_SIM/DES_RAISIN_SIM/FITOPT000.FITRES.gz` (Git blob `7dd16e0978e2be4f09ebdc14698aaeca902df26e`, 2,126,006 compressed bytes). Thus the repository contains both an execution-oriented submit record and the expected nominal fit product, stronger evidence than a matching filename alone.

The companion optical+NIR [`SUBMIT.INFO`](../../runs/research_2026_09_26/raisin_simulation_execution_review/author/output/fit_all/DES_RAISIN_OPTNIR_SIM/SUBMIT.INFO) names `fit/sim/REFAC_DES_RAISIN_optnir.nml`, with 2021-11-11 13:49:26 submit time, 20 completed jobs over the same four versions, `FITOPT000`, and `ALL.DONE`=`SUCCESS`. Its nominal archived FITRES is `output/fit_all/DES_RAISIN_OPTNIR_SIM/DES_RAISIN_SIM/FITOPT000.FITRES.gz` (Git blob `53b5efe4c8804b19873b427fba27e0eb70aad0ed`, 3,508,850 compressed bytes). These are exactly the nominal directory patterns read by [`biascor.py`](../../runs/research_2026_09_26/raisin_differential/mass-threshold/code/raisin_cosmo/biascor.py:26) at lines 26–38 and 133–145, and by [`cosmo_sys.py`](../../runs/research_2026_09_26/raisin_differential/mass-threshold/code/raisin_cosmo/cosmo_sys.py:361) at lines 361–379. The code is an invocation-path witness, not proof of a particular historical invocation.

The pinned [`REFAC_DES_RAISIN_NIR.nml`](../../runs/research_2026_09_26/raisin_simulation_assets/timing/REFAC_DES_RAISIN_NIR.nml:4) maps those four `VERSION` entries to `output/fit_nir/DES_RAISIN_NIR_SIM`, uses `VERSION_PHOTOMETRY='DES_RAISIN_SIM'`, `snoopy.B18`, JH, rest phase −15 to 45 days, and fixes stretch at 1, AV at 0, and peak time (`INISTP_SHAPE`, `INISTP_AV`, `INISTP_PEAKMJD` all zero). The pinned [`REFAC_DES_RAISIN_optnir.nml`](../../runs/research_2026_09_26/raisin_simulation_execution_review/author/fit/sim/REFAC_DES_RAISIN_optnir.nml:4) maps the same versions to `output/fit_all/DES_RAISIN_OPTNIR_SIM`, with grizJH and the corresponding shape, AV, peak-step lines commented out. The `SUBMIT.INFO` records name these NMLs but do **not** store an NML content hash or a per-job command transcript, so the checked-in NML bytes cannot be proved identical to the run-time copies.

## Generator link and alternate snapshots

The pinned master input [`SIMGEN_MASTER_DESSPEC.INPUT`](../../runs/research_2026_09_26/raisin_sign_source/sim/inputs/DES/SIMGEN_MASTER_DESSPEC.INPUT:15) defines `DES_RAISIN_SIM`, applies OIR.J19, and points to [`sim_DES_SNOOPY.input`](../../runs/research_2026_09_26/raisin_sign_source/sim/inputs/DES/sim_DES_SNOOPY.input:32). That input uses `snoopy.B18`, grizJH, and `GENSIGMA_SEARCH_PEAKMJD: 0.01`. A copy of the master input appears at `SIMLOGS_DES_SPEC/SIMGEN_MASTER_DESSPEC.INPUT`, byte-identical to the source input (SHA-256 `13d8f3444666a3fc4b9982b0b808aca45c8e9658d0ca3e53a1a0cc91297045d1`). This supports retention of the intended generator input in a simulation-log directory. It is *not* a generation completion log, seed ledger, or hash-linked record tying those generator bytes to the `DES_RAISIN_SIM` photometry consumed by the 2021 fits.

Three additional archived NMLs under `output/sim/` are separate fitter snapshots. `DES_RAISIN_SIM/DES_RAISIN_SIM.nml` uses SALT2.JLA-B14 and griz; `DES_RAISIN_SIM_NIR/DES_RAISIN_SIM_NIR.nml` uses `DES_RAISIN_SNOOPY_OIR`, JH, fixed shape 1.1/AV 0.16/peak; `DES_RAISIN_SNOOPY_SIM/DES_RAISIN_SIM.nml` uses `DES_RAISIN_SNOOPY_OIR`, grizJH, with the fixing lines commented. None is named by the bias-correction `SUBMIT.INFO` records, and their `VERSION_PHOTOMETRY` differs from the `DES_RAISIN_SIM` used by the archived 2021 outputs. The small `output/sim/DES_RAISIN_SIM/FITOPT.README` says SNANA v10_76d, but that version marker belongs to this separate snapshot; no SNANA executable version is established for the 2021 REFAC fits by the acquired records.

The source-tree inventory for the two bias-fit output directories contains `SUBMIT.INFO`, `ALL.DONE`, FITRES and LCPLOT products, but no per-job logs or saved expanded fit input. The remaining execution link is a generator completion/merge record with input hash, seed/version provenance and photometry product identity, plus a run-time-expanded NML or fit log that hashes the executable input. Without those, the repository strongly supports the *fit-stage* provenance and the intended near-truth timing recipe, but does not prove that the archived bias-correction FITRES were generated by that exact simulation input or that the stored NML bytes were the run-time bytes.
