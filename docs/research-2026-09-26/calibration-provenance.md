# Dovekie calibration artifact provenance and release linkage

The archived Dovekie posterior files contain inspectable calibration-offset samples, but they do **not** establish which stellar-extinction branch produced them or a numerical correction applied to the original DES-SN5YR release. The current [source branch](../../sources/repos/bap37__Dovekie/dovekie.py) forces every stored `_AV` column to zero when `get_all_obsdfs(..., redo=False)` loads the archived extinction-corrected star table. The `redo=True` path calculates extinction and applies selection before writing that table, then `__main__` quits before MCMC. Therefore, **if** a normal-data MCMC used this exact source, its inference would use the zero-`_AV` branch. No saved invocation, exact config snapshot, complete input catalog, run log, or per-draw metadata proves that this later source produced the supplied posterior chains. This is a convention and a provenance gap, not an established release calibration error. A refreshed primary-source check now establishes that omitting stellar MW corrections was described as intentional after a negligible-effect test; see the [updated active investigation](calibration-investigation.md#stellar-extinction-branch-a-deliberate-convention-to-test). That explanation does not identify the execution that produced either stored chain.

The read-only [audit program](../../runs/research_2026_09_26/calibration_provenance/audit.py) inspected NPZ ZIP/NPY headers before calling `np.load(..., allow_pickle=False)`; all members are plain float or fixed-width Unicode arrays. It did not execute Dovekie or load pickle objects. [Hashes, shapes, and findings](../../runs/research_2026_09_26/calibration_provenance/summary.json), all [52 offset summaries](../../runs/research_2026_09_26/calibration_provenance/offsets.csv), and the [DES four-band vectors/covariances](../../runs/research_2026_09_26/calibration_provenance/des_fourband_vectors_cov.npz) are machine readable.

## What the stored arrays establish

Both `DOVEKIE.V9.npz` and `DOVEKIE.V9.2.WD.npz` contain 7,000 × 52 finite float64 samples, 52 identical ordered labels of the form `DES-g_offset`, and the same 12-survey list: PS1, PS1SN, DES, SNLS, SDSS, CFA3K, CFA3S, CSP, CFA4P1, CFA4P2, D3YR, Foundation. They are different sample arrays. These are *additive magnitude-offset parameters* in the source likelihood: `getlikelihood_forone` adds `off2-off1` to the synthetic survey-minus-reference colour relation. The `surfaces-dovekie.py` template writer would insert a positive offset as a positive additive term into the KCOR input if supplied an offset table. This fixes the sign **within that source model**, not the sign of a perturbation to already calibrated DES transient fluxes.

| g | +1.732 ± 2.717 | +2.060 ± 2.708 | +0.328 |
| r | +1.216 ± 2.150 | +1.280 ± 2.166 | +0.065 |
| i | +4.004 ± 2.581 | +3.938 ± 2.538 | −0.066 |
| z | −6.177 ± 3.178 | −6.144 ± 3.173 | +0.032 |

`DOVEKIE_COV_V9.0.npz` stores a 52 × 52 finite symmetric covariance with labels in the same order, transformed from `DES-g_offset` to `DES-g O`. It equals `np.cov(V9.samples, rowvar=False)` within `5.42e-20 mag²`; it is **not** the WD sample covariance (maximum element discrepancy `7.81e-6 mag²`). Thus its lineage to V9 is numerically established, although its name and contents do not give the generating run's settings or convergence diagnostics. The current [plot helper](../../sources/repos/bap37__Dovekie/plotresults.py) and [covariance helper](../../sources/repos/bap37__Dovekie/scripts/helpers.py) implement the matching label transformation and covariance export. The covariance file contains no offset mean vector.

For a gray-free representation let `P = I − 11ᵀ/4` on `[g,r,i,z]`. The V9 posterior mean `Pμ` is `[+1.538,+1.022,+3.810,−6.370]` mmag; WD is `[+1.776,+0.997,+3.655,−6.428]` mmag. The WD−V9 gray-free difference is `[+0.238,−0.025,−0.155,−0.058]` mmag. With r as reference, `[g−r,i−r,z−r]` is V9 `[+0.516,+2.788,−7.392]` mmag and WD `[+0.779,+2.658,−7.425]` mmag. The [NPZ record](../../runs/research_2026_09_26/calibration_provenance/des_fourband_vectors_cov.npz) saves both 4 × 4 native covariances, the gray projection and both projected covariances, and the independent 3 × 3 r-relative covariance for each posterior. Its SHA-256 is in the audit summary. These are posterior *within-branch* covariances; no cross-run covariance or uncertainty for the WD−V9 difference is supplied. A single 7,000-draw array per file is not a convergence or coverage validation.

The parent's [fixed-1,178-star descriptive estimates](../../runs/research_2026_09_26/calibration_stars/synthetic_offset_estimates.csv) answer a different conditional question. With stored extinction they give mean **synthetic-minus-observed** DES-minus-PS1 residuals, in g/r/i/z order, of `[+2.438,+7.470,+0.507,+16.402]` mmag for NGSL and `[+1.485,+5.170,−0.533,+11.749]` mmag for CALSPEC. Those values use a fixed selected cohort, an unweighted linear spectral-library fit, and no joint PS1 anchor, white-dwarf term, full likelihood, or trained SALT response. Their sign convention is also opposite the first-order observed-minus-synthetic additive offset in the Dovekie model. Numeric similarity or difference to V9/WD is therefore not an independent calibration validation or a release correction. The previously reported branch sensitivity is not rerun here.

## Execution and star-input limits

The archived [current config](../../sources/repos/bap37__Dovekie/DOVEKIE_DEFS.yml) specifies **13** surveys including ATLAS, names `DOVEKIE.ATLAS.npz`, enables a white-dwarf observation path, and sets F99. Both stored V9 chains instead encode the 12-survey list above; neither NPZ stores the dust branch, white-dwarf input state, source revision, invocation, sampler acceptance, or chain diagnostics. The pinned source snapshot is a November 2025 repository revision, later than the 2024 original DES analysis. The file name `V9.2.WD` and the [Dovekie paper](../../papers/pdf/2506.05471v1.pdf) support interpreting it as a white-dwarf-related version, but do not prove how that particular array was executed. The paper describes extinction correction through IRSA; the current zero-`_AV` loader branch is not evidence that the published analysis took that branch. The paper's rounded DES Table 3 entries are close to, but do not exactly identify, either stored array.

The archived [query code](../../sources/repos/bap37__Dovekie/queryps1inDES5yr.py) lists ten shallow SN-field centres, then matches an FGCM star catalog to PS1. [PREP_DES_MCMC.py](../../sources/repos/bap37__Dovekie/PREP_DES_MCMC.py) takes `PS1_in_DES5YR.fits[0:2000]` before its magnitude cut and writes `DES_observed.csv`. The archived raw observed CSV has exactly 2,000 rows, all RA 40.203–43.816°, Dec −1.154–0.999°, near the E1/E2 field pair. The `+AV` file has 1,255 rows; coordinate and DES-magnitude matching shows they are a **unique ordered subset** of those 2,000, with maximum differences below `5e-5` from CSV rounding. This is consistent with a subsequent extinction-and-cut pass, but cannot prove the exact execution because the upstream FGCM FITS, matched PS1 FITS, and query/run logs are absent. In particular, this saved table does not represent a demonstrated survey-wide independent stellar calibration sample. The parent's 1,178-star common-cut split is nested within this already selected E1/E2-region file.

## Link to DES KCOR and SALT

The released [DES light-curve-fit input](../../sources/repos/des-science__DES-SN5YR@1.3/7_PIPPIN_FILES/base_files/lcfit/lcfit_desSMP_5yr.nml) names `calib_DES-SN5YR_DES.fits` and `SALT3.DES5YR`; the released [SALT3.INFO](../../sources/repos/des-science__DES-SN5YR@1.3/2_LCFIT_MODEL/SALT3.DES5YR/SALT3.INFO) explicitly describes the nominal surface as using Fragilistic calibration. The available [KCOR input](../../phase2/official/inputs/SNDATA_ROOT/kcor/DES/DES-SN5YR/calib_DES-SN5YR_DES.input) describes its offsets as CALSPEC plus Supercal. Its compiled FITS `ZPoff(Primary)` table is g/r/i/z `[−0.8,−11.6,−9.0,+7.1]` mmag, matching that input's arithmetic. No V9/WD posterior file or Dovekie offset table is named in this original release path; one cannot treat either vector as an applied DES-SN5YR correction.

The later `SALT3.DOVEKIE.tar.gz` is a distinct model: its `SALT3.INFO`, M0 template, and colour-law file have different SHA-256 hashes from the released `SALT3.DES5YR` counterparts (recorded in the [audit summary](../../runs/research_2026_09_26/calibration_provenance/summary.json)). Its embedded `options.json` leaves `calibrationshiftfile` and `calibrationcovariance` empty, and its `testing.log` says no separate calibration shift file was provided. Pre-adjusted KCOR inputs could still have carried changes, so this does not establish no Dovekie calibration in that *later* model; it does establish no direct NPZ-to-SALT input link in these archived options. The [2025 Dovekie paper](../../papers/pdf/2506.05471v1.pdf) presents alternative SALT/KCOR effects and states it did **not** perform a full DES5YR reanalysis. Its exploratory DES comparison is separate from the original DES release.

To close execution provenance, the necessary missing artifacts are the exact Dovekie V9/WD invocation and config snapshot, MCMC logs/diagnostics and stellar input hashes, full FGCM and PS1 matched catalogs, extinction map/query outputs and branch setting, generated `postoffsets.dat` and corrected KCOR inputs/FITS with hashes, SALT training KCOR/offset manifest, and an explicit mapping to any DES fit run. Until those are available, the stored posterior vectors are bounded calibration **hypotheses**, not independently validated corrections to released SN fluxes or an established explanation of residuals.
