# Physical WIRC J observer-operator feasibility

This is a source and calibration feasibility audit. No KCOR table, native executable, fit, or simulation was changed or run. The [manifest](../../runs/research_2026_09_26/csp_wirc_operator_feasibility/manifest.json) hashes the inspected assets; a [frozen numerical protocol](../../runs/research_2026_09_26/csp_wirc_operator_feasibility/bd17-photometry-protocol.json) preceded the only synthetic-star calculation.

**Decision.** A measured physical du Pont+WIRC J throughput and a published photon-count zero point exist locally, so a physical response is feasible in principle. It is not yet an *exact, verified extension of the released RAISIN KCOR*: the released file has no WIRC filter or BD17 reference magnitude, and the published zero-point formula applied to the pinned BD17 spectrum misses the released RC2 reference by 0.00144 mag. That small but real mismatch cannot be removed by an invented offset. Giving WIRC the RC2 BD17 magnitude of 8.4192 while swapping only its throughput is not source-justified.

## Which natural system?

[Krisciunas et al. (2017), section 6.2.3](../../runs/research_2026_09_26/astra_design/csp_optical_filter_identification/Krisciunas2017.pdf) explicitly average the RetroCam RC2 and WIRC J stellar color terms to define **one natural-magnitude system for tertiary standards and SNe**. Their equation (34) is `J_nat,RC2 = J_P98 - 0.015(J-H)_P98`; the text says the WIRC J transformation is identical. RC1 has its own coefficient, −0.039 (equation 33). Section 6.2.2 gives the WIRC color term separately before that decision. NIR photometry is calibrated through P98 secondary standards tied to Vega (section 5), with nightly zero points. This is an explicit *photometric convention*, not a claim that WIRC and RC2 have the same spectral throughput or that a non-P98 primary star must have exactly the same synthetic J magnitude in both.

The pinned [2018 CSP filter README](../../sources/repos/PantheonPlusSH0ES__DataRelease@7fc6805/Pantheon+_Data/2_CALIBRATION/filters/CSP_TAMU_20180316/README:13) identifies the final atmosphere-included scans at 1.2 airmass and lists **13.866 for WIRC J** and **13.836 for RetroCam RC2 J**. It defines `m = -2.5 log10(F) + zp` with `F = (hc)^−1 ∫ S_X(λ) f_λ(λ) λ dλ`. The response therefore enters a *photon-count* integral, with λ in Å and the pinned BD17 `f_λ` in erg s⁻¹ cm⁻² Å⁻¹ ([SNANA source comment](../../sources/repos/RickKessler__SNANA@v11_04k/src/kcor.c:3005)). This formula is independent of an arbitrary normalization only when each published throughput is paired with its own published zero point. The paper reports 2–3% relative repeatability of the NIR bandpass scans (section 4), which is a throughput uncertainty, not a 2–3% magnitude uncertainty.

The pinned SNooPy registry independently identifies [`Jdw`](../../runs/research_2026_09_26/csp_wirc_operator_feasibility/snpy/snpy/filters/filters/LCO/Dupont/filters.dat:5) as `J_DUP_TAM_scan_atm.dat`, with `VegaB=0`; its [`Jrc2`](../../runs/research_2026_09_26/csp_wirc_operator_feasibility/snpy/snpy/filters/filters/LCO/Swope/filters.dat:10) maps to `J_SWO_TAM_scan_atm.dat`, also `VegaB=0`. The exact Git blobs for these registry files and curves are verified in [the acquisition ledger](../../runs/research_2026_09_26/csp_wirc_operator_feasibility/snpy-acquisition.json). Both curves are byte-identical to the respective locally pinned CSP 2018 scans. The registry identifies passband and Vega convention, but it is not a WIRC BD17 magnitude in the RAISIN KCOR system.

## BD17 zero-point bridge

The RAISIN [KCOR input](../../sources/repos/djones1040__RAISIN_DataRelease@a383c4b/kcor/kcor_CSPDR3_BD17.input:1) specifies `MAGSYSTEM: BD17`, `FILTSYSTEM: COUNT`, the BD17 STIS/NIC spectrum and the CSP 2018 filter directory. Its `FILTER` declarations use RC1 as `CSP-J` with BD17 MAGREF **8.4129**, and RC2 as `CSP-j` with **8.4192** (lines 22–23). There is no physical WIRC declaration. The separate pinned [Pantheon+ CSP input](../../phase2/official/inputs/SNDATA_ROOT/kcor/Pantheon+/calib_Pantheon+_CSPDR3.input:35) uses the same RC2 curve but **8.426**, another reason not to transfer a magnitude between release branches by label.

Before calculation, the [protocol](../../runs/research_2026_09_26/csp_wirc_operator_feasibility/bd17-photometry-protocol.json) fixed the README formula, source hashes, trapezoidal integration and an independent union-knot quadrature. The [result](../../runs/research_2026_09_26/csp_wirc_operator_feasibility/bd17-photometry-result.json) with the pinned BD17 spectrum is:

| Band | Published count ZP | BD17 count flux | Source-formula BD17 magnitude |
|---|---:|---:|---:|
| WIRC J | 13.866 | 150.481706 | 8.422291 |
| RetroCam RC2 J | 13.836 | 146.602816 | 8.420644 |

The source-formula WIRC−RC2 BD17 difference is **+0.001647 mag**. An independent integration grid changes each magnitude by <3×10⁻⁷ mag. The RC2 calculation is **+0.001444 mag** relative to the RAISIN KCOR's 8.4192, exceeding tabular print rounding. The calculation thus demonstrates a documented approximate physical reference, not exact recovery of the released reference. We did not diagnose the mismatch by fitting an offset or pick the separate Pantheon+ value as a replacement. A different SED treatment, reference realization, or calibration version remains unresolved.

SNANA [`primarymag_zp`](../../sources/repos/RickKessler__SNANA@v11_04k/src/kcor.c:4317) computes a synthetic primary magnitude from the supplied curve and stores a filter zero point derived from the explicit `FILTER` MAGREF; [`magflux_info`](../../sources/repos/RickKessler__SNANA@v11_04k/src/kcor.c:4514) uses photon weights. The KCOR input's MAGREF is therefore an indispensable independent datum; switching the `FILTER` filename while retaining 8.4192 would *assign* RC2's BD17 magnitude to WIRC. The published CSP count ZP is a separate physical-photometry definition, not syntactically a substitute for the KCOR `FILTER` MAGREF without establishing the primary-system bridge.

## Assets and remaining closure

A physical WIRC table would need, frozen together: (1) the [WIRC response](../../phase2/official/inputs/SNDATA_ROOT/filters/CSP/CSP_TAMU_20180316/J_DUP_TAM_scan_atm.dat) and its CSP README zero-point/airmass definition; (2) the exact [BD17 SED](../../phase2/official/inputs/SNDATA_ROOT/standards/bd_17d4708_stisnic_007.dat) and a documented WIRC BD17 MAGREF on the **same** realization as the RAISIN RC2 input; (3) the [Hsiao reference SN SED](../../phase2/official/inputs/SNDATA_ROOT/snsed/Hsiao07.dat) and a new distinct KCOR band with all required rest/observer integrations; (4) source/version-locked [`kcor.c`](../../sources/repos/RickKessler__SNANA@v11_04k/src/kcor.c) and validation of generated FITS response/ZP against an independent calculation; and (5) the independently established physical-instrument row map and matched real/simulation generation, fit, selection and bias-correction chain. The source Makefile has a `kcor.exe` target (line 708), but no built `kcor.exe` was found under the project-local SNANA build, and none was built here.

The existing CSP paper already accounts for the shared WIRC/RC2 **stellar color transformation** and nightly photometric calibration, and the released KCOR accounts for its declared nominal RC1/RC2 response and BD17 MAGREF. Neither is a WIRC-throughput propagation for SN spectra. The nominal CSP SIMLIB encodes 428 `J` rows and no `j`, without physical-instrument tags ([source audit](csp-filter-bias-propagation.md)); the original photometry-to-RAISIN label bridge maps WIRC `Jdw` to `J` while preserving recorded magnitude/error ([lineage](csp-passband-lineage.md)). There is no WIRC KCOR filter, WIRC-specific passband uncertainty mode, or execution-linked changed-operator bias simulation in the inspected release assets. We also do not have a verified primary-standard derivation that reconciles the README's ZPs with the exact RAISIN MAGREF, nor a WIRC-specific empirical SNooPy model/training closure. These are separate from the known source-derived stellar color convention and from the 2–3% filter-scan repeatability. A physical-operator experiment should preserve those limitations rather than report the RC2 approximation as exact WIRC calibration.
