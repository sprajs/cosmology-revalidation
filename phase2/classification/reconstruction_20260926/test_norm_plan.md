# Prediction-database normalization diagnostic

Before running, source inspection found another difference between onthefly inference and Pippin's `--data_testing` plus `--validate_rnn`: Pippin creates a DES test HDF5 database and `ExperimentSettings.load_normalization` reads that database's normalization. Onthefly instead reads `data_norm.json` beside the training model. Under `norm=cosmo`, this changes the global log-standardization of `delta_time`. The eight flux/error features divide by each light curve's own maximum, but the dataset minimum still controls their initial clipping. This test is source-driven and leaves the original and clump-only results untouched.

Build an isolated test database from the released DATADES raw HEAD/PHOT using the source Pippin command options: `--data --data_testing --phot_reject PHOTFLAG --phot_reject_list 8 16 32 64 128 256 512 --redshift_label REDSHIFT_FINAL --photo_window_files` set to the recreated clump output, `--norm cosmo`, filters `g i r z`. Record exact normalization values and database feature list. Then rerun 1,635 onthefly DES curves with the nine clipping/normalization triples replaced by the test-database values, retaining the same model, inputs, masks, windows, and registered gate. This is a separately labelled diagnostic. The source class-type map affects labels but not normalized feature values; use a complete map over released HEAD SNTYPE codes to permit database generation, with Ia for 1/101 and non-Ia for other codes. If the gate still fails, leave simulations unclassified.
